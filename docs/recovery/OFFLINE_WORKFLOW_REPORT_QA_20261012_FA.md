# StructuralPro — آزمون آفلاین گردش‌کارهای قرنطینه‌شده و خروجی فارسی

**تاریخ:** ۲۰ مهر ۱۴۰۵ / ۱۲ اکتبر ۲۰۲۶  
**مبنا:** بازیابی `StructuralPro-Recovery`، شاخه `fix/offline-sqlite-takeoff-safety-20261012` (PR #2، Draft).  
**محیط:** Linux / Python 3.13.5، بدون اجرای GitHub Actions، بدون ساخت بسته یا انتشار.

## کار اجرایی

1. آرشیو مرجع ۱٬۴۸۷ فایلی به یک پوشه تازه بازگردانی و هش SHA-256 همه فایل‌ها بررسی شد.
2. تعداد دقیق Workflowهای قرنطینه‌شده **۱۹۳** است؛ هیچ فایل YAML در `.github/workflows` مخزن پروژه وجود ندارد.
3. اسکریپت `scripts/run_quarantined_workflow_qa.py` با سیاست Fail-Closed ساخته شد: وجود Workflow فعال، Symlink، تعداد غیرمنتظره یا مسیر هم‌پوشان را رد می‌کند؛ همه ۱۹۳ فایل فقط در یک پوشه موقت کپی می‌شوند؛ اجرای Pytest در همان پوشه انجام می‌شود و محیط موقت حذف می‌شود. این آزمون صرفاً قرارداد فایل‌های تاریخی را می‌سنجد، نه اجرای واقعی/مجوز GitHub.
4. شش تست امنیت و درستیِ خودِ آزمون‌گیر اضافه و اجرا شد.
5. صحت ساختار Excel، CSV و Word فارسی، صفر ابتدای کد ردیف و Fail-Closed نبود شکل‌دهنده PDF با چهار تست بررسی شد.
6. اشکال واقعی DOCX اصلاح شد: `table.direction` خاصیت معتبر python-docx نبود و استثناء مخفی می‌شد. با `table.table_direction = WD_TABLE_DIRECTION.RTL` و تعیین ویژگی‌های `w:bidi` و `w:rtl` جایگزین شد؛ خروجی DOCX به تصویر رندر و خوانایی فارسی مشاهده شد. جزئیات صفحه‌آرایی نهایی در Windows Word تأیید نشده است.

**تفاوت دقیق دو حالت:** ۵۵ شکست آزمون‌های قدیمی مربوط به فقدان فایل‌های `.github/workflows` در مخزن ایمن است. در نسخه آزمایشی با فایل‌های تاریخی این ۵۵ تست موفق‌اند، اما **این به‌معنای رفع ۵۵ اشکال کد یا ایمن بودن تنظیمات واقعی GitHub نیست**.

**۷ آزمون حل‌نشده:** شش آزمون PDF فارسی به نبود دو بسته `arabic-reshaper` و `python-bidi` و یک آزمون Qt به نبود `PySide6` وابسته‌اند. تلاش برای نصب بسته‌های PDF در محیط فعلی با خطای DNS روبه‌رو شد. جایگزین تقریبی برای شکل‌دهی فارسی اضافه نشده تا PDF خراب یا سبزشدن ساختگی تولید نشود.

**یافته بصری:** نمونه DOCX فارسی با ابزار headless به یک تصویر تک‌صفحه‌ای رندر شد؛ محتوا خواناست و جدول جهت RTL OOXML دارد. موقعیت تیترها هنوز نیازمند آزمون دقیق روی Word ویندوز است.

## باقیمانده و شروط پذیرش

- در محیط Windows با بسته‌های نصب‌شده، شش تست PDF و تست Qt دوباره اجرا شوند؛ خروجی PDF فارسی از نظر شکل‌دهی، فونت، سرصفحه و شکست صفحه به‌صورت تصویری کنترل شود.
- محدودیت‌های Qt، کنترل واقعی DWG/PDF viewer، RTL منوی برنامه و بازکردن پروژه در Windows آزمایش شود.
- به هیچ وجه ۱۹۳ Workflow را صرفاً برای سبزشدن تست در مسیر فعال مخزن کپی نکنید.
- تغییرات این مرحله را فقط در یک PR پیش‌نویس جدا روی PR #2 ثبت کنید؛ `main` و PRهای پیشین دست‌نخورده بمانند.
- تست آفلاین صرفاً قراردادهای تاریخی را می‌سنجد و جایگزین GitHub Environment reviewers و Branch Rulesets نیست.
