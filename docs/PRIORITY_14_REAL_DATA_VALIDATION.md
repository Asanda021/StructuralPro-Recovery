# Priority 14 — Real Data Validation

## هدف
اطمینان از اینکه داده‌ای که در پروژه واقعی وارد یا تولید می‌شود، قبل از عبور به مرحله بعدی، از نظر ساختار، مقدار، واحد، یکتایی و ارتباط بین مراحل قابل اعتماد باشد.

## کنترل‌های اصلی
- شناسه پروژه و نام پروژه
- شناسه و منبع متره
- جلوگیری از دوباره‌شماری منبع
- مقدارهای عددی متناهی و غیرمنفی
- کنترل واحدهای شناخته‌شده
- شرح اجباری برای متره و BOQ
- کنترل ردیف‌های خالی BOQ
- شناسایی کدهای BOQ تکراری
- شناسایی BOQ با منبع orphan
- کنترل هزینه‌های برآورد
- کنترل مبلغ اسناد مالی
- کنترل شناسه‌های تکراری مالی
- کنترل ارجاعات شکسته اسناد مالی به تعهد/هزینه/دریافتی
- کنترل کاندیداهای استخراج‌شده از نقشه
- امتیاز کیفیت داده و شمارش خطا/هشدار

## شدت‌ها
- error: داده نباید به‌عنوان معتبر تلقی شود.
- warning: داده قابل پردازش است اما نیازمند بازبینی است.

## سرویس برنامه
StructuralProApp.validate_project_data(project_id) کنترل‌های فوق را روی نسخه persisted پروژه اجرا می‌کند.

## مرز مرحله
این مرحله validation داده و integrity بین workflowها است؛ کنترل طراحی سازه، صحت مهندسی نقشه یا تأیید آیین‌نامه‌ای نیست.

## معیار پذیرش
1. پروژه معتبر بدون خطا سبز شود.
2. مقدار منفی، غیرعددی یا غیرمتناهی خطا تولید کند.
3. واحد ناشناخته خطا تولید کند.
4. منبع متره تکراری خطا تولید کند.
5. ارجاع مالی شکسته خطا تولید کند.
6. orphan BOQ به‌عنوان warning مشخص شود.
7. کاندیدای نقشه با source تکراری شناسایی شود.
8. تست اختصاصی و regressionهای قبلی سبز باشند.
