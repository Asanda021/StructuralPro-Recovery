اجراها هم‌پوشان‌اند و با هم جمع نمی‌شوند. در رگرسیون میانی۱۳۴۴ PASS/یک FAIL داشتیم: تبدیل بیش‌ازحد سخت‌گیرانه تفریق حجم Float قدیمی را رد می‌کرد. رفتار معتبر تفریق حفظ و فقط حذف کامل کسر غیرصفر مسدود شد؛ آزمون قدیمی تغییر نکرد. ردکردن افت دقت در جمع‌ها با پل موجود `legacy_float` انجام می‌شود؛ موتور موازی ساخته نشد. دقت عمومی تمام مسیرهای Float هنوز اثبات نشده است.

ورودی‌های ZIP با SHA اعلام‌شده و همه۱۲ عضو دو Manifest تطبیق داشتند. `.pytest_cache` وارد Git نشد. فایل کد عددی ZIP با Git بایت‌به‌بایت برابر بود؛ فایل آزمون در ZIP دارای sys.path و قالب‌بندی متفاوت است، ولی AST تمام توابع/پارامترها/Assertها برابر است. نسخه Git استفاده شد. یک فرمان اولیه پیش از قرارگیری فایل با Exit4 بدون اجرای آزمون پایان یافت؛ این خطای آماده‌سازی از شکست محصول جداست. ZIPهای اصلی و شواهد قرمز/سبز در بکاپ نگهداری می‌شوند.

`record_revision=True` و `1.0` در بسته مالکیت به‌علت برابری Python با1 پذیرفته می‌شدند؛ دو آزمون قرمز و کنترل type دقیق این نقص را رفع کردند. چهار مثال حذف جزء یا کسر در جمع/تفریق نیز بازتولید شدند. هیچ آزمون قبلی حذف/ضعیف نشد.

## داده و قفل مالی

دو کنترل جدید تابع خالص‌اند و دفتر SQLite، مسیر مالی یا Schema موازی ایجاد نکرده‌اند. تست SQLite از برنامه واقعی و دو اتصال استفاده می‌کند، اما رکوردهای آن Snapshot مصنوعی آزمون‌اند؛ ساخت از فرم/موتور تخصصی همه شش خانواده ادعا نمی‌شود. با تغییر Revision عضو، سند قبلی رد می‌شود؛ ذخیره نسخه قدیمی با CAS رد و BOQ/برداشت‌های قدیمی fixture حفظ می‌شوند. داده تاریخی واقعی ARCH-5/STAIR-5 در این نوبت دوباره پذیرش نشد و بازنویسی نشده است.

ready=false، commit_allowed=false، payable_rows=[] در بسته‌های تازه حفظ‌اند. نام متفاوت Scope عدم تداخل هندسی را ثابت نمی‌کند. شناسه و بایت معتبر، اصالت نقشه، امضای مهندس یا حق پرداخت را ثابت نمی‌کند. کنترل‌های shared_rebar، concrete_formwork و commit_guards موجود در رگرسیون حفظ شدند. اتصال سرویس/فرم اختصاصی این دو قرارداد تازه و دفتر پرداخت مشترک کامل همچنان انجام‌نشده‌اند؛ این بسته‌ها جایگزین آن‌ها نیستند.
