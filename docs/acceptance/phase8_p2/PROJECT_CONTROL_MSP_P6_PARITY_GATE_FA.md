# StructuralPro | گیت پذیرش کنترل پروژه در سطح MS Project و Primavera P6
**تاریخ:** ۱۰ آبان ۱۴۰۵ / ۱ نوامبر ۲۰۲۶  
**تصمیم مالک:** قابلیت کنترل پروژه باید از نظر صحت محاسبات و گردش اجرایی با Microsoft Project (Desktop) و Oracle Primavera P6 قابل مقایسه باشد؛ صرف گانت نمایشی/مجموعه فعالیت پیش‌فرض قابل قبول نیست.  
**دامنه:** زیرمجموعه موجود C13–C21/C25 از فاز ۸/اولویت ۲ و رگرسیون یکپارچه فازهای پیشین؛ هیچ فاز یا اولویت جدید تعریف نمی‌شود.  
**وضعیت ثبت:** REQUIREMENTS_REGISTERED؛ PARITY_NOT_VERIFIED؛ RELEASE=NO_GO.  
**قیود ثابت:** برنامه Windows-first فارسی/RTL، یک نسخه نهایی، بدون Android، بدون Merge/main/EXE/Installer/Release مگر با اجازه صریح مالک، بدون آپلود مدارک خصوصی.

## وضعیت فنی ثبت‌شده، بدون بزرگ‌نمایی
- **موجود/در حال توسعه:** `core/projects/precedence_model.py` روابط FS/SS/FF/SF با lag و محاسبه **شروع زودترین** در workday offset را دارد؛ **این الگوریتم اثبات CPM کامل/Backward Pass/Total Float/Longest Path نیست**.  
- `core/projects/crew_capacity.py` کنترل تداخل pool نام‌دار و یک سناریوی محدود تراز deterministic ایجاد می‌کند؛ **این به معنی تراز چندمنبعی بهینه در سطح MS Project/P6 نیست**.
- `core/projects/iran_worksite_calendar.py` تقویم شمسی پروژه و تعطیلات قابل بازبینی دارد؛ تقویم رسمی سال‌های آینده نیازمند کنترل نسخه است.
- `core/projects/production_catalog.py` نرخ‌های پیشنهادی غیررسمی تولید دارد؛ نرخ‌ها باید با داده واقعی پروژه کالیبره شوند.
- فرم‌های گانت، برنامه هفتگی، سرپرست‌ها و گزارش PDF/XLSX در PR42 پیاده‌سازی اولیه دارند؛ **Baseline قراردادی، Actuals، EVM، CPM مستقل، import/export P6/MSP و parity کامل در این ممیزی ACCEPTED نیستند**.
- همه assertions فوق فقط درباره فایل‌ها و شواهد بررسی‌شده‌اند، نه ادعای نبود هر قابلیت در سایر نقاط repo. هر قابلیت یافت‌شده باید با تست واقعی اثبات و ماتریس زیر به‌روز شود.

## معیار برابری؛ دو سطح شفاف، بدون ادعای کاذب
**سطح ۱: موتور حرفه‌ای Desktop (MS Project-grade).** باید PC01–PC09، PC12–PC16 (برای قابلیت‌های مربوط) و هسته صحیح PC10/PC11 با شاهد واقعی پاس شوند. این «گانت شکیل» نیست؛ **برنامه قابل اتکا** است.

**سطح ۲: Primavera P6 enterprise-grade.** علاوه بر سطح ۱، مدیریت حقیقی چندپروژه، ظرفیت سراسری، دسترسی هم‌زمان امن، EPS/OBS و نقش‌ها، ریسک و سناریو، تبادل XER/XML و گزارش تحلیلی مستند الزامی است. نسخه ویندوزی آفلاین می‌تواند بعضی قابلیت‌ها را به‌صورت محلی پیاده کند، اما بدون آزمون معماری هم‌زمان/سازمانی نباید با P6 EPPM «برابر» معرفی شود.

## قرارداد فنی: نتایج نامعتبر همیشه مسدود
- **نقشه/متره ناقص →** مدت و منابع منتسب به آن مورد `PROVISIONAL` یا `BLOCKED`؛ **بدون تاریخ پایان قطعی**.
- **نرخ تولید بدون مدرک واقعی →** تنها سناریوی پیشنهادی با disclosure، نه تاریخ مصوب کارفرما.
- **No Actual Costs →** AC/CPI/EV مالیِ قطعی تولید نشود. پیشرفت فیزیکی از پرداخت مالی جدا است.
- **هر اصلاح نقشه/BOQ/منبع/تقویم/پیش‌نیاز →** محاسبات وابسته stale و پذیرش‌های مرتبط invalidate شوند، نه اینکه گزارش قبلی خودبه‌خود معتبر بماند.
- **AI** فقط پیشنهاد مستند بدهد؛ تغییر تاریخ، نقدینگی، ادعای تأخیر و مسیر بحرانی بدون موتور deterministic و مجوز بازبین ممنوع است.
- خروجی باید سند منشأ، نسخه، نقش و زمان داشته باشد؛ تاریخ مصوب فقط از Baseline مصوب قابل استناد است.

## ترتیب اجرای کار **در همان** اولویت موجود
1. ممیزی واقعی کد/دیتابیس/رابط/تست برای PC01–PC16؛ ماتریس GAP با نشانه `ALREADY_VERIFIED/PARTIAL/NOT_IMPLEMENTED/BLOCKED`، بدون حدس.
2. ابتدا موتور CPM/تقویم و Data Date/Baseline را با تست شبکه مستقل صحیح کن؛ بعد resource leveling و مقدار→مدت؛ سپس Actuals/EVM و Lookahead.
3. بعد چندپروژه، ریسک، quality audit، import/export و UI حرفه‌ای را بر پایه هسته پذیرفته‌شده تکمیل کن؛ هر بخش با RED→GREEN+Windows+Linux.
4. برای آزمون واقعی، از پروژه ساختمان پنج‌طبقه «شهدا» فقط داده‌های تأییدشده استفاده کن؛ تاریخ کارفرما، حضور پیمانکار و نرخ تولید مجهول را ساختگی جایگزین نکن. برای داده‌های محرمانه از Library خصوصی استفاده کن.
5. یک Golden Project با حداقل ۱۰۰ فعالیت و oracle مستقل بساز؛ سه Snapshot پیشرفت، تغییر مقدار متره، تغییر منابع و سه Baseline/سناریو را آزمون کن؛ برای سطح سازمانی هم benchmark چندپروژه الزامی است.
6. آزمون تبادل XML/XER را تنها وقتی فایل مجاز و نرم‌افزار مرجع در محیط اجرای واقعی موجود باشد ACCEPTED کن؛ در غیر این صورت `NOT_VERIFIED`.
7. پیش از اعلام قبولی هر PC، فایل تست، شمار آزمون، JUnit، SHA یکسان، نتیجه CI، خروجی واقعی و بازبین را ثبت کن. **سبزشدن تست‌های قدیمی مجوز قبول PCهای جدید نیست**.

## خط قرمز نقشه‌راه و انتشار
این ۱۶ مورد **گیت پذیرش و شکاف‌های اجرایی کنترل پروژه فعلی** هستند، نه ۱۶ اولویت یا ۱۶ فاز تازه. تعداد فازها **۸** و اولویت‌های فاز۸ **۶** ثابت است. تا تست واقعی، وضعیت `MSP_PARITY=NOT_VERIFIED` و `P6_ENTERPRISE_PARITY=NOT_VERIFIED`، P8/P2=PARTIAL و درصد مرجع کل **۸۹٫۶٪** بدون تغییر.  
**NO_MERGE / NO_MAIN_WRITE / NO_EXE / NO_INSTALLER / NO_RELEASE** بدون تأیید صریح مالک.

### خلاصه پروژه و گفتگو
خواسته مالک: کنترل پروژه حداقل هم‌سطح MSP و Primavera و متصل به متره واقعی، با محاسبات دقیق و شاخص‌های مدیریت کارگاه. این سند تنها الزام را ثبت می‌کند؛ تحقق آن نیازمند کد، آزمون، شواهد و مقایسه مستقل است.
