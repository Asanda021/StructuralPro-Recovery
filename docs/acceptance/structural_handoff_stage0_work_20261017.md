## تغییر واقعی این مرحله

۳۷ فایل افزایشی هفت پچ به ترتیب تحویل وارد Worktree جدا شدند؛ هیچ موتور قبلی جایگزین نشد. سه موتور دیوار برشی، پله بتنی و شمع و چهار نگهبان مالکیت، همان کد تحویل Chat هستند. هشتاد‌وپنج خانواده و هشت فاز تغییری نکردند.

متد `StructuralProApp.preview_structural_handoff` به Snapshot جاری همان ProjectStore/SQLite وصل شد. منبع JSON با SHA-256 و برابری محتوا کنترل می‌شود؛ کلید JSON تکراری، float باینری و مقادیر نامتناهی رد می‌شوند. تغییر هم‌زمان پروژه یا سند، نتیجه را باطل می‌کند. نگهبان‌های اصلی و BOQ مشترک تنها روی کپی حافظه‌ای پیش‌ارزیابی می‌شوند؛ هیچ ریزمتره یا مبلغی ذخیره نمی‌شود.

فرم فارسی RTL از فرم اصلی AEC با دکمه «پیش‌ارزیابی بسته‌های سازه‌ای؛ ثبت مالی مسدود» باز می‌شود. بازکردن سند، محاسبه واقعی، جدول کاندیدهای دقیق، نمایش موانع، پاک‌کردن و بستن فعال‌اند. اعداد پیش‌فرض وجود ندارند. این **فرم حسابرسی** است؛ فرم تخصصی ورود قطعات و گردش قطعی سه موتور هنوز کامل نشده است.

نمونه `examples/structural_handoff_audit_work_synthetic.json` صریحاً مصنوعی است و تأیید پروژه واقعی نیست. خروجی آن ۶۶ کاندید، ۹ درخواست تطبیق میلگرد و ۵۷ درخواست بتن/قالب دارد. این اعداد مربوط به همین داده نمونه‌اند، نه تعداد ایرادهای پروژه واقعی.
