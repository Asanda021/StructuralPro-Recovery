## تصمیم اجرایی

- StructuralPro یک محصول جامع متره، برآورد و دفتر فنی کل ابنیه و AEC است. **تیر فقط یک عضو است**. PR #11 متره تیر به‌صورت مستقل و Draft باقی می‌ماند؛ این سند با آن PR مخلوط نمی‌شود.
- معماری موجود، منطق محاسباتی مشترک، SQLite، واحدها، فهرست‌بها و زیرساخت نقشه حفظ می‌شوند. توسعه بدون بازنویسی سراسری و بدون ایجاد محاسبه‌گرهای موازی انجام شود.
- اصل قطعی: **Fail-Closed**؛ هیچ طول، ضخامت، تعداد، قالب‌بندی، مصالح، مصرف، پرت، مقیاس یا قیمت حدس زده نشود. هر مقدار باید منبع/واحد/مبنای محاسبه/وضعیت بررسی داشته باشد. فقدان داده ≠ صفر؛ وجود فرمول ≠ قابلیت کامل و قابل استفاده.
- فعلاً کار روی جامعیت موتور و مسیرهای دستی/نقشه‌محور انجام شود. اجرای گرافیکی ویندوز و ساخت/انتشار به خواست مالک فعلاً موکول می‌شوند؛ پیش از اتکای مهندسی/انتشار الزاماً باید انجام شوند.

## ۱. مرز شواهد

این سند حاصل بازرسی فایل‌های منتخب GitHub است، نه اجرای همه آزمون‌ها، نه بررسی همه توابع ۱۴۸۱ فایل و نه مقابله با نسخه اصلی ازدست‌رفته. وضعیت‌ها تنها به میزان شواهد فعلی اعتبار دارند.

- هسته عمومی: \`core/takeoff/engine.py\` به \`core/takeoff/modules/{building,advanced,civil,mechanical,electrical}.py\` متصل است؛ \`core/platform/application.py\` مسیرهای پروژه، متره، BOQ، برآورد و صورت‌وضعیت دارد.
- کار دستی: \`core/takeoff/manual_input.py\` و \`manual_workbench.py\` ورودی متنی چند عضو را پشتیبانی می‌کنند؛ \`core/takeoff/assembly_templates.py\` قالب‌های مبتنی بر ورودی صریح برای برخی مصالح/نازک‌کاری‌ها دارد.
- رسم/منبع: \`core/drawings/viewer_model.py\`, \`dwg_takeoff.py\`, \`pdf_engine.py\`, \`takeoff_session.py\`, \`takeoff_bridge.py\` و \`core/bim/ifc.py\`.
- دفتر فنی: \`core/projects/store.py\` (SQLite)، \`core/takeoff/boq.py\`، \`core/estimate/user_pricebook_import_v1.py\` و \`core/reports/exporters.py\`.
- فهرست رشته‌ها: \`core/aec/disciplines.py\` ۱۱ حوزه ثبت می‌کند اما نام‌گذاری در این فهرست اثبات وجود محاسبه‌گر اجرایی دقیق نیست؛ \`core/product/full_building_takeoff_v2.py\` یک قرارداد پوشش/ردیف است، نه خود موتور محاسبه همه اجزا.
- \`tests/test_golden_five_storey_building.py\` وجود دارد؛ آزمون آن در این حسابرسی اجرا نشده است.
- PR #11 روی شاخه \`feature/beam-detail-fail-closed-20261013\` در حالت Draft است؛ کدهای این PR بخشی از \`main\` نیستند. در برآورد قابلیت‌های \`main\` نباید آن را بی‌قید ادغام‌شده فرض کرد.

### یافته‌های فنی نیازمند اصلاح در اولویت نخست

1. \`core/takeoff/manual_input.py\`: ورودی سریع دستی فقط بخشی از اعضا را نگاشت می‌کند؛ حتی وقتی موتور سطحی برای یک آیتم وجود دارد، کاربر لزوماً مسیر تخصصی ورودی دستی آن را ندارد.
2. \`core/takeoff/modules/building.py\`: برخی سقف‌های پیچیده با هندسه کلی/محاسبه ترکیبی ساده متره می‌شوند؛ باید پیش‌شرط اعتبار دیتایل‌ها و استثنائات هندسی صریح باشد. تعداد تیرچه در یک مسیر از فاصله استنتاج می‌شود؛ کاربر باید آرایش واقعی، لبه‌ها و کلاف‌ها را تأیید کند.
3. \`core/engineering/domains/steel.py\`: مسیر جوش دارای \`p.get("weld_unit_weight", 1.0)\` است؛ وزن واحد پیش‌فرض در متره مهندسی نهایی، بدون تأیید منبع، با سیاست منع حدس سازگار نیست. این **کاندید اصلاح اولویت‌بالا** است.
4. \`core/aec/disciplines.py\`: نگاشت حوزه‌های timber / historic به \`advanced\` وجود دارد، ولی وجود مورد پشتیبانی‌شده متناظر در \`modules/advanced.py\` با این نگاشت اثبات نمی‌شود. باید پشتیبانی واقعی بررسی و موارد ناموجود صریحاً مسدود شوند؛ نام روی منو نباید قابلیت جعلی نشان دهد.
5. \`core/product/full_building_takeoff_v2.py\` صرفاً از وجود ردیف برای پوشش رشته‌ها گزارش می‌دهد؛ برای سنجش **قابلیت واقعی** به ماتریس item × input × calculator × source × persistence × report × tests نیاز است، نه شمارش رشته‌های ثبت‌شده.

## ۳. مسیر واحد طراحی؛ عدم ایجاد موتورهای موازی

هر «آیتم اجرایی» باید حداقل دارای:
- کد یکتای نوع عضو، سیستم/رشته، پروژه، ساختمان/طبقه/ناحیه، هویت منبع نقشه یا متره دستی، اثر انگشت و نسخه نقشه.
- کمیت مستقل برای هر مصالح و عملیات: بتن، میلگرد، قالب، بلوک، ملات، گچ، رنگ، فولاد، پیچ، جوش، تجهیزات و غیره؛ ترکیب غیراستاندارد در یک ردیف ممنوع.
- ورودی‌ها و واحدهای صریح، پیش‌شرط‌ها، منابع هر مقدار، کسرهای مثبتِ مستند، فرمول و وضعیت بررسی.
- نتیجه قابل ممیزی: \`draft / needs_detail / needs_review / confirmed / blocked\`؛ مقدار تأییدنشده هرگز به‌عنوان نهایی وارد برآورد نشود.
- انتقال به \`TakeoffEngine → takeoffs → BOQ → pricebook → estimate → statement → exports\` فقط بعد از عبور گیت‌ها.
- یک پیاده‌سازی مشترک برای قواعد واحد/کمیت/ذخیره؛ توسعه از طریق رجیستری عضو و الگوی ورودی، نه کپی‌کاری کلاس‌های جدا.

## ۵. معیار «تمام‌شده» برای هر قابلیت

وجود کد، منو، تست ایزوله یا نام یک رشته به‌تنهایی PASS نیست. برای هر آیتم:
1. ورودی کامل دستی و/یا منبع نقشه قابل انتخاب؛ منبع و واحد روشن.
2. محاسبه مهندسی مستقل برای اجزا با کسر/افزودنی معتبر و بدون پیش‌فرض پنهان.
3. داده ناقص/تکراری/متعارض با خطای فارسی و عدم ورود به BOQ.
4. ماندگاری SQLite با نسخه، تاریخچه و ردگیری.
5. اتصال واقعی به قیمت‌نامه **واردشده توسط کاربر**، ریزمتره، صورت‌وضعیت و خروجی قابل استفاده.
6. آزمون کمیت با مرجع مستقل + آزمون یکپارچه؛ برای عرضه یا اتکای واقعی آزمون ویندوز و خروجی RTL نیز لازم خواهد بود.
