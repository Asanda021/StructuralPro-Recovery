## قواعد هسته مشترک

- \`ReviewedStructuralWorkflow\` برای عضوهای **غیرتیر** از همان \`ProjectStore\`، \`TakeoffEngine\` و \`build_boq\` اصلی استفاده می‌کند. متره تیر همان \`BeamDetailWorkflow\` موجود PR #11 باقی می‌ماند؛ هیچ موتور محاسبات مستقلِ موازی جایگزین نمی‌شود.
- نوع‌های مجاز: \`column\`, \`tie_beam\`, \`isolated_footing\`, \`strip_footing\`, \`mat_footing\`. نوع‌های تعریف‌نشده با خطا رد می‌شوند، نه اینکه به فرمول مکعبی عمومی ارجاع داده شوند.
- واحد همه ابعاد هندسی متر، بتن مترمکعب، قالب مترمربع و وزن میلگرد کیلوگرم است. \`count\` باید صحیح و مثبت باشد؛ مقدار NaN/inf/bool پذیرفته نمی‌شود.
- کسر بتن: فهرست صریح \`intersections\` با \`id, volume_m3, source_ref, approved_by\`. کسر بیش از حجم ناخالص، شناسه تکراری یا کسر تکراری بین رکوردهای قطعی مسدود است.
- قالب: فهرست \`surfaces\` از سطوح خالص **واقعاً در تماس با قالب** با \`id, net_area_m2, source_ref\`؛ نبود قالب فقط با دلیل، منبع و تأییدکننده صریح قابل پذیرش است.
- هر گروه میلگرد باید \`confirmed\` یا \`not_applicable\` مستند باشد. حالت \`unreviewed / needs_review\` با صفر برابر نیست. هر سری میلگرد، تعداد، وزن واحد و منبع وزن، مرجع دیتایل و طول برش تأییدشده دارد. اگر طول برش از اجزای جداگانه ساخته شود، آن اجزا باید \`length_parts_m\` شامل \`kind, length_m, source_ref\` و \`approved_by\` باشند؛ **هیچ ضریب خم/مهاری/وصله حدسی** مجاز نیست.
- \`source.mode=drawing\` برای اعضای غیرتیر نیازمند مسیر واقعی فایل، SHA-256 واقعی، صفحه و مستطیل انتخابی است؛ در پیش‌نمایش/commit دوباره تطبیق داده می‌شود. در صورت تغییر منبع، تأییدهای پیشین باید بازنشانی شوند.
- ذخیره پیش‌نویس با \`expected_revision\`؛ عملیات commit پس از preview کامل، در یک ذخیره ProjectStore، \`takeoffs\` و \`boq\` موجود را به‌روز می‌کند و دوباره‌ثبت‌کردن را مسدود می‌کند.
- ستون/پی چندتایی: سطح قالب و تعداد میلگرد در داده‌های ورودی **جمع تأییدشده کل گروه از اعضا** هستند؛ هیچ تکثیر پنهان بر اساس تعداد بتن انجام نمی‌شود. در گزارش نمونه‌ها باید از دوباره‌شماری اجتناب شود.
- موجود بودن \`core/engineering/domains/{foundations,concrete,steel}.py\` تضمین درستی مقادیر خاص نیست؛ هسته DomainQuantity اکنون مقادیر غیرمتناهی را رد می‌کند.

## آزمون‌ها و مرز ادعا

- \`tests/test_reviewed_structural_five_priorities.py\` به مخزن اضافه شده و انواع عضو، طول برش جزءبه‌جزء، مصالح مستقل، وجود/عدم وجود آرماتور، بازبینی، جریان SQLite/BOQ، تعارض نسخه، اثر انگشت فایل نقشه، سناریوی PDF دو صفحه و امنیت NaN/inf را هدف می‌گیرد.
- در محیط محلی، **۷۹ آزمون مربوط به PR #11 قبلی با harness وابستگی ایزوله** اجرا شدند و همگی PASS شدند. این عدد **اثبات عبور آزمون‌های کد تازه این PR نیست**؛ اجرای آزمون‌های تازه با نسخه کامل کد مخزن و رابط ویندوز هنوز انجام نشده است.
- تا زمان تأیید، نه شمارش فایل‌ها، نه Commit، نه آزمون‌های قدیمی به معنای کامل‌شدن پنج قابلیت محصول نیست.
- نقشه‌های واقعی پروژه ساختمانی، دیتایل‌های انواع تیپ‌های ستون/پی/شناژ، فایل IFC و خروجی فارسی BOQ/Excel/PDF هنوز نیازمند پذیرش مرجع مستقل هستند.

## موارد باز جهت تکمیل واقعی پنج اولویت

1. استخراج واقعی پلان و دیتایل میلگرد از نقشه‌های دارای معماری‌های متفاوت، نه فقط TEXT/MTEXT صریح؛ تشخیص دوباره استفاده شدن یک دیتایل توسط چند عضو و عدم ترکیب تیپ‌ها.
2. جداسازی خم/مهاری/وصله و تعداد خاموت/شبکه از شاپ‌دراوینگ یا جدول معتبر، همراه با تشخیص ابهام و تائید مهندس؛ بدون حدس AI.
3. قواعد حرفه‌ای هندسه خالص قالب/بتن در اتصال اعضا، پی نامنظم، آرماتور مش و ستون چندطبقه.
4. ایجاد و آزمون واقعی فرم‌های فارسی برای ستون و پی؛ اتصال انتخاب ناحیه به فرایند کاربری عمومی.
5. اجرای مجموعه آزمون‌های تازه روی کد کامل GitHub و مقایسه با ریزمتره مرجع مستقل؛ پیش از انتشار نیز آزمون محیط Windows و خروجی‌های RTL.

خاموت ستون و شناژ، پیش از محاسبه وزن، باید جدول جانمایی واقعی با شروع/پایان ناحیه، موقعیت اولین/آخرین خاموت، فاصله، تعداد صریح، طول برش و مرجع معتبر داشته باشد. اعتبارسنجی از \`core/takeoff/stirrup_zones.py\` موجود در PR #11 استفاده می‌کند. این کنترل تعداد خاموت را از فاصله حدس نمی‌زند. دو سناریوی آزمون ستون/شناژ اضافه شده‌اند اما عبور آن‌ها روی کد کامل هنوز ادعا نشده است.


### ۱۳ اکتبر — تکمیل کنترل گروه‌های تکراری و آزمون محلی

- برای تعداد ستون/شناژ/پی بزرگ‌تر از یک، سطح قالبِ تأییدشده باید صریحاً \`area_scope=total_group\` و \`area_scope_ref\` داشته باشد. برای میلگرد تأییدشده نیز \`count_scope=total_group\` و \`count_scope_ref\` الزامی است؛ تعداد هر عضو با کل مجموعه یکسان فرض نمی‌شود.
- یک جدول یک‌عضوی خاموت نمی‌تواند خاموت دو ستون را توجیه کند؛ برای جدول جانمایی خاموت/تنگِ تأییدشده باید هر عضو فیزیکی جداگانه ثبت شود.
- کدهای \`core/takeoff/reviewed_components.py\`, \`core/takeoff/reviewed_structural.py\` و \`core/drawings/member_evidence.py\` از GitHub با SHA محتوای واقعی تطبیق داده شدند و در محیط محلی به‌صورت مستند اجرا شدند.
- **۷۹ آزمون pytest موجود PR #11 موفق** (وابستگی ایزوله). افزون بر آن، **۱۴ بررسی کد واقعیِ نقشه/اجزای متره** و **۱۵ بررسی ستون/پی/شناژ و بازبینی اعضای تکراری** به‌صورت اجرای مستقیم Python موفق بودند. این ۲۹ مورد به‌عنوان آزمون مستقل محلی گزارش می‌شوند، نه CI یا آزمون کامل ۱۳ فاز.
- فایل آزمون افزوده‌شده در GitHub برای کل پنج اولویت هنوز در محیط مخزن کامل با pytest اجرا نشده است؛ برای تأیید نهایی همچنان به آن اجرای یکپارچه و نقشه/متره مرجع نیاز است.
